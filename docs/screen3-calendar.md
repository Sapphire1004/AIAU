# 画面 3（カレンダー）機能要件 検討資料

画面 3 の機能要件を決めるための論点整理資料。各論点に選択肢と推奨案を挙げているので、**決定** 欄を埋めて確定させ、確定内容を [requirements.md](requirements.md) に反映する。

現時点の [requirements.md](requirements.md) の記載は以下のみ。

- 日 / 週 / 月などの単位でプランをカレンダー表示する。
- カレンダー上の予定から、元の付箋・プランの詳細を参照できる。
- プランの変更はカレンダー表示に反映される。

---

## 0. この画面の位置づけ（前提の確認）

画面 2 で投票により確定したプランを、カレンダーの形で「見る / 使う」ための画面。

まず決めたいのは **画面 3 の役割をどこまで広げるか**。以降の論点はここに依存する。

| 案 | 内容 | 特徴 |
| --- | --- | --- |
| A. ビューア | 表示専用。編集は画面 2 で行う | 実装が軽い。編集導線が画面 2 に一本化され迷いがない |
| B. 軽編集つきビューア | 表示に加え、時間の微調整や予定の追加・削除ができる | 当日の微修正が画面 3 で完結。画面 2 と編集機能が二重化する |
| C. カレンダーアプリ | 旅行プラン以外の予定も扱う汎用カレンダー | スコープが大きく広がる。外部カレンダー連携がほぼ必須になる |

推奨: **A から始め、B を将来拡張**。「カレンダーアプリとして表示できる」という要望は、まず「カレンダーの見た目・操作感で確定プランを扱える」ことで満たせる。

## 1. 表示単位（ビュー）

| 論点 | 選択肢 | 推奨 |
| --- | --- | --- |
| 対応するビュー | 日 / 週 / 月 / アジェンダ（リスト） | 日・月・アジェンダの 3 つ。週は旅行用途では優先度が低い |
| 初期表示 | 今日 / プラン開始日 / 直近の予定 | プラン開始日（旅行前に開いても中身が見える） |
| 旅行期間の扱い | 期間全体を 1 画面に収める「旅程ビュー」を用意するか | 2〜3 泊なら日ビューの横並びで代替できるため、初期は不要 |

補足: 旅行プランは「複数日 × 1 日の中の細かい時間割」という形になるため、月ビューは概観、日ビュー / アジェンダビューが主戦場になる想定。

## 2. カレンダー上に表示する情報

予定 1 件あたりに何を出すか。

- 必須: タイトル、開始・終了時刻
- 候補: 場所名 / 地図リンク、所要時間、費用、メモ、担当者・参加者、元付箋へのリンク、確定 / 仮の状態
- 移動時間の扱い:
  - 表示しない
  - 予定と予定の隙間として表示する
  - 「移動」という予定として明示的に置く（推奨: 実際の破綻が見えるため）
- 終日予定（宿泊、チケット期限など）の扱いを決める必要がある

## 3. 画面 2 との関係（同期の方向）

| 論点 | 選択肢 |
| --- | --- |
| 画面 2 → 画面 3 | 確定プランのみ反映 / 未確定案も薄く表示 |
| 画面 3 → 画面 2 | 反映しない（ビューア） / 双方向に同期 |
| 未確定・複数案が残っている場合 | 非表示 / 「未定」枠として表示 / 得票トップの案を仮表示 |
| 元データへの導線 | 予定 → 付箋詳細 → チャットの該当発言、までたどれるか |

推奨: 反映は確定プランのみ。ただし未確定の時間帯を空白にすると抜けに見えるため、「未定」プレースホルダを置く。

## 5. 共有・外部連携

| 論点 | 選択肢 | 備考 |
| --- | --- | --- |
| 外部カレンダー連携 | なし / ics エクスポート / Google カレンダー双方向同期 | ics エクスポートは実装が軽く効果が大きい。双方向同期は認証・競合解決が重い |
| 共有 | アプリ内のメンバー限定 / 閲覧専用リンク / 画像・PDF 出力 | |
| 通知・リマインド | なし / アプリ内 / プッシュ・メール | 外部カレンダーに出せば通知はそちらに任せられる |

推奨: 初期は **ics エクスポート + 閲覧専用リンク**。双方向同期は要望が出てから。

- 編集権限を全員に与えるか、作成者のみか
- 同時編集時の競合の扱い

## 7. 対応端末・表示要件

- 想定利用シーン: 計画時は PC、当日は**スマホ**。当日利用がある以上、スマホ表示は必須
- スマホでの主ビュー（日ビュー / アジェンダビューが有力）
- オフラインでの閲覧可否（旅行先で電波が弱い状況を想定するか）

## 8. スコープの目安

上記の推奨案を採った場合の初期スコープ案。

**初期リリースに含める**

- 日 / 月 / アジェンダの 3 ビュー
- 確定プランの表示、未確定枠のプレースホルダ表示
- 予定から元の付箋・チャット発言への導線
- ics エクスポート
- スマホ対応

**将来拡張**

- 画面 3 上での編集
- Google カレンダー等との双方向同期
- 通知・リマインド
- 参加者別の別行動レーン
